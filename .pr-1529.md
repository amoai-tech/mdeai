## The problem

The authenticated voting job holds **production-wide Supabase credentials** — the service-role key
bypasses every RLS rule — and it ran on `pull_request`. Any same-repository PR touching a listed
path received those keys, and its checked-out code (helpers, npm scripts, dependencies) ran with
them. A path filter is not an authorization boundary, and an environment approval still executes the
PR's code once approved.

Separately, **successful runs discarded their screenshots**: the upload ran only `if: failure()`, and
the receipt screenshots exposed the real receipt UUID.

## What changed

1. **No PR code runs with the keys.** The trigger is now `workflow_dispatch` and `push: main`. No
   `pull_request` path filter, so an untrusted branch can never reach the credentials.
2. **Two uploads instead of one.** Success publishes an **explicit allowlist** of four sanitized
   screenshots (`if-no-files-found: error`). Failure publishes only screenshots plus the HTML report —
   **traces and error contexts are deliberately excluded** because they can contain authentication data.
3. **Receipt screenshots mask the real receipt id** via Playwright's `mask`. The confirmation
   screenshot is left unmasked on purpose: no receipt exists at that point.

## Honest limits — this reduces exposure, it does not fully isolate

- `SUPABASE_SERVICE_ROLE_KEY` is still a **repository** secret, because four other workflows
  (`floor`, `live-integration`, `prod-synthetic-smoke`, `vercel-production-certification`) depend on it.
  Moving it to an environment would silently override it for the others while leaving them on the
  production key — not isolation.
- A required-reviewer environment is **not usable here**: the repository has exactly **one admin**, so
  `prevent_self_review` would make the job unapprovable.
- **The real fix, tracked as follow-up:** give this test a dedicated development Supabase project so
  per-PR runs can return. Until then, per-PR voting proof is replaced by a human-triggered run.

## Not weakened

`--retries=0` stays, the non-skipping configuration check stays, and the real database-backed journey
is unchanged.
